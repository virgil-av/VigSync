# AI Priming: Raspberry Pi POC Branch (Server Collector Version)

This document serves as an architectural manual and context injection for any AI agent working on the `raspberry-pi-poc` branch.

## 1. Branch Objective
The `raspberry-pi-poc` branch transforms VigSync from a peer-to-peer syncing app into a **Server Collector**. 
- **The Phone (Samsung A55)** acts as a silent observer, capturing events locally.
- **The Raspberry Pi (RPi)** acts as the network bridge, consuming data from the phone via USB (ADB) and publishing it to the MQTT network.

## 2. Key Architectural Shifts
Compared to the `develop` branch, this version has the following radical changes:

### A. Network-Less Phone App
The Android app has **zero network connectivity**. 
- Removed: MQTT Client libraries, Internet permissions, and pairing logic.
- Result: Increased battery life and stealth, as all data transfer happens over a physical USB cable.

### B. USB Data Bridge (ADB)
Data is moved from the phone to the RPi using the Android Debug Bridge (ADB).
- **Log File**: Events are saved to an encrypted JSONL file in the app's external Documents folder.
- **Config File**: A JSON configuration containing MQTT broker details and encryption keys is generated by the app for the RPi to consume.

### C. External MQTT Consumer (Python)
The actual MQTT connection is managed by a Python script (`rpi_script/vigsync_consumer.py`) running on the RPi.
- It uses `adb shell tail -f` to stream the log file in real-time.
- It acts as a "transparent bridge," publishing encrypted data to the network.

## 3. Data Flow & Encryption
1. **Capture**: `SyncManager` captures a Call, SMS, or App Alert.
2. **Encrypt**: Data is encrypted using **AES-GCM** with a unique `shared_key`.
3. **Log**: Encrypted data is written to the log file in format: `topic_suffix|encrypted_payload`.
4. **Stream**: The RPi script reads the tail of the log file via USB.
5. **Publish**: The RPi script publishes the payload to the correct MQTT topic (`events` or `status`).
6. **Client Decrypt**: Paired client devices (using the original VigSync app) receive the MQTT message and decrypt it using the key provided via the "My QR" feature.

## 4. Key Components for AI Review
- **`com.vigsync.core.SyncManager`**: Orchestrates local capture and handoff to the exporter.
- **`com.vigsync.core.EventExporter`**: Handles the physical file writing and encryption.
- **`com.vigsync.core.ServerConfigManager`**: Generates the bridge configuration for the RPi.
- **`com.vigsync.core.VigSyncService`**: A simplified local foreground service.
- **`rpi_script/vigsync_consumer.py`**: The RPi-side logic.

## 5. Development Rules for this Branch
- **No Internet in App**: Never add `INTERNET` permission back to the Android app.
- **Maintain Compatibility**: The `RawMessage` model and QR pairing schema must remain compatible with the standard VigSync client app.
- **UTF-8 Safety**: Always use UTF-8 when handling log file streams to avoid decoding crashes with encrypted data.
- **Branch Isolation**: Ensure all POC-specific files remain tracked in this branch only.

## 6. How to Pair
Use the **"My QR"** button on the Dashboard. This generates a JSON object containing:
- `id`: Device ID
- `name`: Device Name
- `topicPrefix`: The MQTT namespace
- `key`: The AES Encryption Key

Client devices scanning this QR will automatically configure themselves to listen to the RPi's published stream.
